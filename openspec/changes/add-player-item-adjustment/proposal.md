# 提案：新增玩家道具调整功能

## 摘要

基于 `Admin.NET/doc/GmItemAuditApi.md` 为管理后台新增 GM 玩家道具调整能力。该变更会扩展现有 CenterServer GM RPC 集成，新增后端提交接口、独立前端操作页面，并在调整成功后与现有道具流水页面联动，方便立即审计核对。

## 背景与原因

当前项目已经具备服务器管理和道具流水查询能力，但管理员还不能在同一套后台中直接执行“玩家道具调整”操作。这个缺口会导致补偿、纠错等场景仍然依赖外部工具或人工流程，操作链路分散且不利于审计。

这次变更的目标是补齐这条链路，同时保证过程可追踪：

- 使用文档推荐的 `ICenterGmService.AdjustPlayerItem` CenterServer 调用路径
- 从当前登录后台用户中记录操作人身份
- 强制填写 `ReasonCode`，并支持补充 `Remark`
- 调整完成后可直接跳转到现有道具流水页面进行核验

## 目标

- 为后台补充 `AdjustPlayerItem` 能力
- 新增一个独立的后台页面，用于在指定服务器上调整玩家道具数量
- 返回并展示 `BeforeNum`、`AfterNum`、`AppliedDelta`、`ChangeTimeTicks`、`RoleId`、`ItemId`
- 支持从调整结果快速跳转到道具流水页面
- 实现方式与现有 `GameServerAddress`、`GameServerItemAudit` 模式保持一致

## 非目标

- 不支持直接走 `IGmService` 的 GameServer 直连模式
- 不支持批量调整或导入式操作
- 不包含道具元数据管理，例如物品名查询
- 不为 GM RPC 返回的业务校验失败增加自动重试

## 范围

### 本次包含

- CenterServer RPC 合同补充道具调整相关定义
- 后台动态 API 增加提交玩家道具调整请求的接口
- 前端 API 模块、路由、菜单以及玩家道具调整页面
- 调整结果跳转到审计页面的联动支持

### 本次不包含

- 除跳转和预填外，不改造现有道具流水查询行为
- 不新增后台持久化表
- 不引入审批流、二次复核或批量审核队列

## 预期结果

变更完成后，具备权限的操作员可以打开独立页面，选择服务器，输入 `RoleId`、`ItemId`、带正负号的 `Delta`、`ReasonCode`、`Remark` 以及可选的 `TraceId`，提交后立即看到服务端确认的前后数量变化，并通过链接跳转到道具流水页面完成校验。
